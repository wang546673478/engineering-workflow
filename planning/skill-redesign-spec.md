# SPEC-SKILL-REDESIGN-01：工程工作流的动态基线与即时纠偏

状态：用户已于 2026-10-23 审核完整改造方案，并明确允许开始实施。需求来源为 [原始改造需求](../planning/skill-redesign-assessment.md) 附件及随后关于上下文复用和实施中纠偏的说明；本 Spec 与 Issue #24 的批准独立。

## 目标

让 `engineering-workflow` 在实际作业中以低成本查询当前代码/任务事实，并在新证据表明当前 Baseline、Spec、Plan 或 Task 不准确时，及时核对和纠正受影响权威内容，再继续依赖该结论的工作。门槛用于防止 Agent 跑偏，不以留痕或材料完整度本身为目的。

## 需求

- **REQ-SR-01 动态全局基线**：Baseline 覆盖项目声明范围内的模块/功能地图、数据库结构和前后端契约，并区分可由代码/声明来源计算的事实、需解释的业务判断和任务状态。事实视图来源明确、可按稳定 ID 查询、支持范围与未知边界可见；不把无法提取解释成空集合。
- **REQ-SR-02 低成本新鲜度与纠偏**：Agent 可复用同一任务、同一工作树和来源未变且无新证据反例的上下文/缓存。相关源码变化、范围/决定变化或测试/运行反例出现后，受影响切片失效；在再次依赖它前重新查询、比较并刷新或核实更正。无须每个微小操作重复查询。
- **REQ-SR-03 实施中修正权威事实**：代码、测试或运行证据发现 Baseline 事实/语义错误时，先查证并修正 Baseline 当前权威视图与受影响引用，再继续依赖该结论的工作；若实际代码违反已批准 Spec，应记录为缺陷而非改写目标；证据冲突时只暂停可能依赖错误结论的动作，独立工作继续。
- **REQ-SR-04 保留联动工件且单一权威**：Baseline 表达当前事实，Spec 是确认需求正文唯一权威，Plan 是技术路径唯一权威，Task 是执行状态唯一权威。通过单一 change set 入口更新一次变更涉及的权威视图及必要引用；不复制正文，不为无关视图制造写入或版本号。只有用户改变批准边界时才重开 Spec 语义 revision。
- **REQ-SR-05 稳定 ID 与切片查询**：模块、表/字段和受支持接口/路由可用稳定 ID 读取精确事实切片、来源证据、计算/adapter 版本、覆盖范围和限制；一次读取尽量返回相关判断及引用。尚不支持的来源显式标 unsupported/unknown。
- **REQ-SR-06 Delta 门槛**：阻塞 finding 必须指出对象、当前/预期或缺失值、证据、受影响动作及解除条件。可自动重算的事实自动重算；语义判断和一般待补证据不作为全局停止；只有密钥入库、越权访问、当前动作实际适用的 required 测试未跑/失败及项目既有明确危险操作规则，阻止受影响动作。由错误事实造成的局部依赖动作可在核验期间暂停，但这不是新增通用硬门槛。
- **REQ-SR-07 按 Task 范围适用门槛**：区分 hotfix/minor/feature/takeover；标准 gate 的适用范围清楚，低规模不豁免安全、真实 required checks 或用户决定；纯调查/Baseline 纠正不因全局阶段误要实施授权。`depends_on` 仅表达具体技术产物依赖，`after` 仅表达非阻塞顺序偏好。开发影响范围与 staged 提交范围分开；可识别临时文件不制造假阻塞，源文件不静默忽略。
- **REQ-SR-08 可达、兼容且受治理的工具**：required 项存在现实可达的通过路径。手工 inventory 在声明来源/边界可定位且 mapping 与列出条目一致时沿用 checker 现有 `pass`，同时说明不证明范围内绝无遗漏。旧 manifest 保持兼容；checker 规则变化可审阅且不会为通过门禁而临时改写检查器。报告重跑覆盖稳定 current，不自动删除历史用户文件；成本统计仅使用可信宿主日志，为可选诊断。
- **REQ-SR-09 新项目和 Baseline 完整含义**：无既有实现时记录空实现起点及约束；首次实现后转 partial，交付前完成项目声明范围的事实基线。完整表示声明范围内各适用视图均有来源、状态、边界和影响说明，不表示所有视图都已被适配器支持或完成运行时证明。

## 保留边界

不删除 Baseline/Spec/Plan/Task；不自动证明业务正确、不代替用户业务决定或隐式授权；不降低现有项目 required tests、超时、控制面保护或危险操作限制；不迁移外部项目。未知视图只有在影响当前安全或正确决策时才局部阻止依赖它的动作。已确认业务解释可据新证据指出描述错误；新的业务规则/权限选择仍按现有工作流向用户确认。

## 验收

- **AT-SR-01**：SQLite fixture 修改后，按 table ID 查询即返回当前字段并含来源/指纹；静态关系受支持的输入能按稳定 module/symbol ID 查询。未支持路由/契约输出明确边界。
- **AT-SR-02**：源指纹未变且无反例时允许复用缓存；源变化后下一次依赖该切片前 query 自动重算；冲突证据使旧判断不可复用。
- **AT-SR-03**：三种纠偏路径（Baseline 错、代码违反 Spec、证据冲突）分别正确更新权威视图、限制依赖动作并允许独立工作继续。
- **AT-SR-04**：单一 change set 分发到唯一权威与必要引用，给出完整 diff；hash 冲突整批拒绝；不复制正文、不自动批准。
- **AT-SR-05**：每个阻塞 checker finding 均提供对象/证据/动作/解除条件；required manual inventory 有既有 `pass` 可达路径及范围 limitation。
- **AT-SR-06**：四种任务规模和 applies-to 矩阵测试通过；after 不阻塞开工，真实 artifact 缺失只阻止消费者；调查任务不误触发实施授权门槛。
- **AT-SR-07**：worktree-impact 纳入新源码、commit scope 只看 staged 并报告未暂存差异；可识别临时项不阻塞且仍可见。
- **AT-SR-08**：旧 manifest 无迁移仍保持既有批准、required checks 和安全策略；报告 current 覆盖，不自动删除历史报告。
- **AT-SR-09**：Skill、references、模板、项目基线/追踪和发布记录同步；原 required TEST / COMPILE / GUIDANCE-COMPILE 通过；skill validator 和新行为回归通过；程序验证与语义核验分别报告。
- **AT-SR-10**：配对 feature 的调用数下降目标仅在有完整宿主日志与同类样本时测量；否则标为未验证，不以估算验收。

本 Spec 以用户审核的完整方案为业务/流程范围；实施中按证据修正当前事实和 Plan 实现细节，不静默扩展用户批准边界。
